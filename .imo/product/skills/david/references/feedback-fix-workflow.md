# 新增反馈的同类修复闭环

适用于处理已有 review 的新增评论，尤其是重复出现的问题。字段和运行行为以工程源码为准；这里规定检查顺序，不引入新的审批流程。

1. 经评论 CLI 读取当前版本，和已处理快照比较。新条目、新用户编辑、新用户回复都计入；Agent 自己的回复与单纯状态变化不触发重新实现。记录每个待办的 id、当前原文与定位信息。
2. 把具体症状归为可检查的问题模式，在源 JSON 中盘点所有页面、同类组件与展示层，按需读取相关源码；不以浏览器逐页巡检代替数据盘点。字段/行为遗漏沿用 [来源覆盖检查](authoring-extraction.md)，增量合并沿用 [候选验证](authoring-incremental.md)。每类记录受影响范围、修复位置、验证证据。
3. 区分工具行为与方案事实：业务内容、字段、技术代码及画板节点/关系默认只修 JSON；只有共用交互/布局缺陷才修 React/CSS。保持已有锚点、无关内容与用户评论。复用技术方案先核对目标仓库公开导出、props、消费者调用链与端/版本；内部组件的存在不代表可公开导入。
4. 在候选稿执行结构、引用与锚点校验，检查实际生成数据。所有同类位置完成结构覆盖；仅行为/布局变化涉及的分支补定向自动化验证，Computer Use 的启用与停止条件统一见[最小改动与验证](authoring-incremental.md#最小改动与验证)。框架回归使用隔离服务，不向用户评论库写测试数据。
5. 发布前重读 JSON/评论，保留并发用户变更。验证通过后逐条追加 Agent 结论，写清覆盖范围与未验证边界，并回读确认；不替用户 resolved。只有全部新增用户意见都已处理才更新处理水位。

| 模式 | 必查范围与判定 |
|---|---|
| 假控件/准备事项藏在需求里 | 全部脚手架行；迁移到 preparation 真 checkbox/input；键盘输入、勾选、刷新保留、跨页同项共享、窄宽度可用 |
| 短文仍开详情/长段落/留白 | 所有 requirement/change 展示层；短文直接显示、行为按有序列表、代码解释放 hover、容器自然高度；旧评论定位能回到新内容 |
| 长引用焦点溢出 | 路径/URL/无空格标识在默认省略、键盘展开与复制失败状态都不超出容器；完整值仍可读取和复制，不用裁切隐藏焦点全文 |
| 简单功能重复层级 | 根组件及嵌套层的单行叶子在父层展示完整内容，行标题只展开/收起；有独立 deepDive、画板或显式 drilldown 时保留入口，旧节点 ID 与评论定位不删除 |
| 框选或填写反馈时评论按钮遮挡 | 评论展开/折叠两态、框选启动/追加/取消、反馈填写/关闭；按钮隐藏且不可键盘聚焦，退出恢复原状态，普通富详情/设计资料仍允许操作评论；隐藏后移除反馈关闭按钮为其预留的额外空间，宽窄屏按正常边距与 safe-area 对齐 |
| 具体实现缺少代码 | `implementationInventory` 覆盖所有页面/父子 mapping；逐行记录已有、补齐或无需代码的理由，检查输入转换、状态、调用、失败/取消与依赖契约。不能仅填当前锚点，不能把代码字符串存在当作完成证据 |
| 逻辑图与画板复用 | 节点、边与说明优先改 JSON 的 graph/codeFlow，复用既有画板；只有共享能力存在缺陷才先修 CanvasViewport/useCanvasTransform/LogicCanvas。数据改动检查引用；渲染器改动再验证固定视口、缩放边界、长标签、hover/键盘、窄屏与旧评论定位 |
| 单代码详情高度 | 单个代码块尽量使用窗口剩余高度；多块保留局部滚动，弹窗与关闭按钮始终在视口内，注释与前后对照滚动不退化 |
| 回调只声明未实现 | 核对所有同类动作的默认函数、真实 SDK/schema 调用与父层绑定；跨页共享实现只保留一份可达正文。接口未知的动作明确待确认，不用另一层空回调掩盖 |
| 代码范围高亮过脏 | 同一注释的连续非空代码段只绘制一个柔和整体边框；遇到 diff 占位或源空白行断开，禁止逐行描边，保留真实增删色、对齐、滚动和键盘说明 |
| 迁移代码缺说明 | 同类复用/改造行的 before 与 after；两侧完整代码、真实增删标记及对侧空行、相同行同高、垂直滚动同步，行级注释范围正确、hover/键盘仍可读，不复制一份同义说明 |
| API 数据不全 | 全部可见动态内容逐项列源：字段/派生/常量；重复商品/商家/主播身份、头像、图标、标题与跳转分开核对，类型含子字段且锚点指向最小元素 |
| 接口字段列表过长 | 所有接口卡片共享 Disclosure；标题和 method/path 同为折叠入口，所有字段契约默认折叠；状态徽标始终可见；键盘可展开/收起，字段高亮重渲不重置收起状态，评论定位字段自动展开其祖先 |
| 目标端用错实现 | 技术代码与目标端当前源码/官方文档互证；公开入口及实际版本分支，网页预览不能作为 Lynx 原生验证证据 |
| 首次渲染跳变 | 普通/长内容滚动预览、子节点、富详情、总览对齐；首帧前定最终容器和阅读边界，动画只影响视觉位移/缩放，不能把动画中 rect 用作相邻列宽度；首次评论加载预留默认 rail，快照到达不挤正文，确认空列表才释放；逐帧检查正常动画、reduced-motion、延迟评论响应及 resize |
| 预览中的工具说明冗余 | 逐页检查 pageHtml 组件上下的参数演示器、状态示例与渲染脚注；移除非产品内容，必要约束合入对应设计/注释，保留产品控件与字段锚点 |
| 顶栏重复或样式脱节 | 每页同类入口及工具/资料按钮统一使用主题 tokens；入口按当前页实际 component 锚点或 scene 归属列出，不用 kindLabel 文案去重误删不同内容；每个入口可达，缺失业务锚点在 JSON 补齐 |
| 补充表单复杂或覆盖评论 | 以用户提供的名称与文件为主路径，系统自动识别/建组；复用共享非模态面板，低于评论/反馈，交互验证点击、键盘、框选与草稿 |
| 评论/状态陈旧 | 已打开页面接收外部 Agent 回复，无需 reload 或先回复；标签更新且未提交草稿、阅读位置、折叠状态不丢失；旧快照不得回退新版本 |

从 `<canonical>/project` 可运行 `node scripts/audit-review-authoring.mjs <review.json>` 检出假控件、过长摘要、代码外重复说明和泛化类型。审计不证明字段完整、公开导出或真机行为；零命中仍需来源和产物核对，但不因此自动触发 Computer Use。

交付证据保留简短模式覆盖表及未验证项即可，不粘贴完整 JSON、大段日志或重复的实施过程。可复用结论改进本 skill 对应条款，避免逐次追加互相矛盾的规则。

涉及图标、版式或视觉争议时，先从本机设计资料库按页面读取原始 PNG/CSS，再核对原始导出；派生 spec 或当前 HTML 只能帮助定位，不能替代原设计证据。新增资料与分组的流程见 [design-materials.md](design-materials.md)。

针对整块 hover 过于抽象的反馈，遍历所有页面技术点与 before/after 两侧，按真实逻辑分段，保留代码全文。多代码关系图修复同时验证：逐节点多选/取消、键盘激活、拖拽不误选、旧评论自动选中正确代码，以及无关联上下文节点不会切换到错误代码。短画板布局需验证长短组件切换、评论栏展开/收起、窗口 resize 与富详情边界。
