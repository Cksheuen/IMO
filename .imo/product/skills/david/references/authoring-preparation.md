# 工程准备与脚手架取舍

新建项目、修改构建配置或准备事项时使用；已有工程无相关变更则不加载、不输出这类内容。结构以 [review-schema.md 的工程准备](review-schema.md#工程准备) 为准。

## 先提取已有资料

首次创建先从当前上下文与项目读取下列信息。未提供的资料放 `preparation.fields`，待创建项放 `preparation.tasks`，使用真实 input/checkbox；不把待创建内容放入需求列，不用 ☐ 或下划线假装控件。仅当缺口阻塞当前任务且无法自行查明时提问，不臆造占位名称。

| 资料 | 用途与条件 |
|---|---|
| OWNERS / owner | 责任人；首次创建必需，已明确的直接预填 |
| 应用名 / app name | 产物归属、标题与 slug；首次创建必需 |
| 仓库归属 / repo | 源码根与复用探测起点；首次创建必需 |
| 参考项目 | 有则沿用其组织方式，省略重复目录说明 |
| 硬件视口 / viewport | 用户提供时锁定，含宽高/DPR/安全区 |
| 设计稿来源 | 原始 Figma、PNG、CSS 文件或链接，按页面归属 |
| 契约来源 | 涉及后端时核对 IDL/DTO/文档；未定按 proposed 处理，不因此阻塞无依赖工作 |
| 数据样本 | 只在理解/复现确需时取最小脱敏样本 |

同一应用的公共工程准备只在一个主要位置展示，其他页面仅描述页面入口、路由或发版差异并引用该位置；不要在每页复制同一套任务和表单。兼容存量重复准备项时复用 `preparation.id`，不同事项不能共用 id。准备控件的填写或勾选不等于代码/资源已经创建；用户要求后续申请的 channel 等留在准备字段中，不猜名。

## 只输出新建项或实际差异

- `Lynx.config.mjs`、vite/rspack 等常规构建配置无特殊处理就不输出；确有特殊片段时，仅用代码富文本展示相关部分。
- 不逐条解释 `package.json` 依赖；新增、改名、版本锁定等实际变更才放在所属功能/工程准备行，用改动表达说明原因。
- 目录结构仅在没有参考项目或差异很大时说明；有参考且沿用时不重复列树。
- 待办按动作分条、资料按字段预填；不要为展示“做过调研”新增工程底座组件或长篇脚手架介绍。
