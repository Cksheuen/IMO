# Project Profile Runtime Contract

`runtime/project-profile/` defines the stable contract for local project
convention snapshots consumed by IMO rules such as Chameleon.

## Purpose

Project profiles cache low-frequency observations about the current repository:

- source layout
- command and verification style
- validation and error-handling boundaries
- testing conventions
- IMO/Trellis ownership boundaries
- generic agent habits that local evidence should override

Prompt-time hooks must not scan the repository. They may only read a bounded
profile summary generated by an explicit refresh command.

## Source And State Boundary

Tracked source:

- `.imo/runtime/project-profile/CONTRACT.md`
- `.imo/runtime/project-profile/schema.json`
- `.imo/product/scripts/project_profile.py`
- profile contract and smoke checks wired into `./imo verify`

Ignored local runtime state:

```text
.imo/.runtime/project-profile/current.json
.imo/.runtime/project-profile/summary.md
.imo/.runtime/project-profile/manifest.json
.imo/.runtime/project-profile/history/
```

Generated profile state is rebuildable and must not become source-of-truth.

## Command Contract

The user-facing command surface is:

```bash
./imo profile refresh
./imo profile status
./imo profile inspect
./imo profile clear
```

Rules:

- `status` and `inspect` must not create runtime state.
- `refresh` is the only default command that writes profile runtime state.
- `clear` removes local profile runtime state only.
- No profile command may write Trellis-owned files or host-output projections.
- No prompt-time hook may call `refresh`.

## Status Model

| Status | Meaning | Context behavior |
| --- | --- | --- |
| `missing` | no profile exists | inject missing-state hint only |
| `current` | profile matches cheap fingerprint checks | inject bounded summary |
| `stale` | profile may drift from repo state | inject summary plus stale warning |
| `invalid` | schema or required files are broken | do not inject profile summary |

Staleness checks are intentionally cheap:

- schema version
- generated summary exists and is bounded
- selected source fingerprint
- git head
- TTL

## Refresh Scope

`refresh` should collect representative evidence, not index the whole repo.

Default evidence sources:

- README and runbook docs
- `.imo/ARCHITECTURE.md`
- `.imo/BOUNDARY.md`
- `.imo/product/rules/**`
- `.imo/product/scripts/*`
- `.imo/runtime/**` contracts
- `.trellis/spec/**` contracts as data only
- config and lock files when present

## Chameleon Interaction

Chameleon may use the profile as a starting point, but the active task still
requires local evidence from neighboring files and existing tests.

Priority:

```text
explicit user instruction
> repository hard rules / specs
> current local neighboring patterns
> project profile
> active IMO learning digest
> generic agent training defaults
```

If neighboring files contradict the cached profile, trust the current local
evidence and treat the profile as possibly stale.
